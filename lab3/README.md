# Lab 3 — Guestbook (XSS Prevention)

## 1. Project structure

```
index.php                    public page
guestbook.php                guestbook form + list of all stored messages
protected.php                authenticated-only page
logout.php                   destroys the session
auth/login.php               login form
auth/signup.php              registration form
helper/db.helper.php         user DB connection + schema
helper/guest.db.helper.php   guest DB connection + schema
helper/auth.helper.php       password hashing, login/logout, session helpers
repository/user.repo.php     user queries (prepared statements)
repository/guest.repo.php    guest message queries (prepared statements)
database.sqlite              users database (auto-created on the first request)
guest.sqlite                 guest database (auto-created on the first request)
```

The `vulnerable/` folder from the previous phase and the old `secure/` folder
(now `auth/`) are gone — this project keeps only the secure implementation.

## 2. What this phase added

- `guestbook.php` — guestbook form + list of all stored messages
- `helper/guest.db.helper.php` — SQLite connection + schema for the **guest** database
- `repository/guest.repo.php` — `createGuestMessage()` / `getAllGuestMessages()` (prepared statements)
- `guest.sqlite` — the **guest** database (auto-created on the first request)

Schema (database `guest`, single table `guest`):

```sql
CREATE TABLE guest (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    "user"            TEXT NOT NULL,
    text_message      TEXT NOT NULL,
    e_mail            TEXT NOT NULL,
    data_time_message DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

The form reuses the existing bare input markup from `auth/signup.php`, and `index.php` links to the guestbook, the login and the signup pages.

## 3. How XSS is prevented

1. **Output escaping (main defense):** every value coming from the database or from the previous request is printed through `htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')`. This also covers values placed inside HTML attributes.
2. **Store raw, escape on output:** messages are saved unchanged in SQLite, so the data stays correct for other consumers; escaping happens in the HTML context only.
3. **Input validation (defense in depth):** required fields, max lengths (name 50, message 1000), and `filter_var(..., FILTER_VALIDATE_EMAIL)` for the e-mail.
4. **Prepared statements:** the `INSERT` uses bound parameters, so the guestbook is not SQL-injectable either.
5. **Server-side timestamp:** `data_time_message` is generated by PHP, never taken from the request.
6. **POST → redirect → GET:** a successful post redirects to `guestbook.php`, preventing duplicate inserts on refresh.

## 4. How to test it

1. Start the server and open `http://localhost:8000/guestbook.php`.
2. Post a normal message — it appears in the table with its date.
3. Post these payloads and confirm they are displayed as **text**, not executed:

```html
<script>alert('XSS')</script>
<img src=x onerror="alert(document.cookie)">

```

## 5. Accounts

`index.php` → **Sign up** → `auth/signup.php` → **Login** → `auth/login.php` →
`protected.php`. Passwords are stored with `password_hash()` and verified with
`password_verify()`; the session id is regenerated on login to mitigate session
fixation.
